Win10bet 现在应该怎么用

你要的最终用法，我已经整理成最省事的方式：

1. 整个项目放到 GitHub
2. 用 Render 连接这个 GitHub 仓库
3. 让 Render 跑这个项目
4. 用户和你自己都访问 Render 的网址

最重要的一句：
GitHub 负责放代码和自动更新部署，Render 负责让网站在线、让后台收到用户数据。

为什么不能只放 GitHub Pages

GitHub Pages 只能放静态网页。
它不能运行 Node.js 后台，也不能统一保存：
- 用户注册
- 手机号登录
- 积分
- 投注单
- 后台日志
- 自动更新赛事

所以如果你要“别的设备也能打开，而且后台也能收到全部人的数据”，必须用 Render 这种在线服务器。

现在你的正式访问方式

前台：
https://你的Render域名/win10bet.html

后台：
https://你的Render域名/admin.html

健康检查：
https://你的Render域名/api/health

GitHub 的作用

GitHub 主要做这几件事：
- 保存项目代码
- 让你以后继续修改
- 每次 push 后自动触发 Render 重新部署
- 做备份，防止本地文件丢失

所以 GitHub 不是没用，它是“代码仓库 + 自动部署入口”。

Render 的作用

Render 才是正式在线服务器，它会：
- 运行 `npm start`
- 对外开放网站给别人访问
- 提供 `/api/state`
- 提供 `/api/fixtures`
- 让后台收到注册、登录、积分申请、下注和日志

自动赛事现在怎么工作

现在后端会自动处理赛事，不需要你天天手动改：
- 优先从 ESPN 抓取接下来几天的 NBA 和世界杯赛事
- 自动生成赔率市场
- 自动补充其他项目赛事
- 如果线上数据临时失败，会自动切到后备赛事，不会让页面空掉
- `/api/fixtures` 现在带缓存和更新时间，减少反复请求

免费版 Render 要知道的事

免费版可以先上线测试给别人打开。
但是免费版使用临时存储，服务重启后这些数据可能会被清掉：
- 用户
- 积分
- 请求记录
- 部分后台数据

如果你以后要长期正式运营，建议升级到带 persistent disk 的方案。

你现在上传到 GitHub 后，应该保留这些文件

- `package.json`
- `render.yaml`
- `win10bet-server.js`
- `admin.html`
- `assets/*`
- `docs/*`

Render 现在的基本配置

Build Command:
`npm install`

Start Command:
`npm start`

环境变量建议：
- `ADMIN_USER`
- `ADMIN_PASSWORD`
- `DATA_DIR`
- `FIXTURE_CACHE_TTL_MS`

如果你以后还想加 GitHub Pages

可以，但只建议拿来放前台静态页。
真正的数据和后台还是要走 Render。

也就是说：
GitHub Pages = 前台壳
Render = 真正后台和统一数据

最省事的最终方案

直接把整个项目放 GitHub，然后由 Render 自动部署。
以后你改代码并 push，Render 就会自动更新。
用户统一访问 Render 上线地址，这样后台才能收到所有人的数据。
